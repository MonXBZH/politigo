# La Brocante Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** A public trading board where players of both camps swap wardrobe items (plus bulletins as a complement or a price), with notifications, a public feed line for cross-camp trades, an admin card and a « same network » signal.

**Architecture:** Pure, shared rules in `web/market.mjs` (validation, matching, the two-state trade) used by the server and the browser. A storage module `server/market.mjs` (own SQLite tables, like `server/snowchallenges.mjs`). Routes `GET/POST /api/market` in `server/server.mjs`; a trade runs both players' `update()` inside one `BEGIN … COMMIT`, like `transferBaton`. Browser view helpers in `web/marketui.mjs`, the sheet in `web/app.js`.

**Tech Stack:** Node 24 (`node:sqlite`, `node:crypto`), vanilla ES modules, `node --test`; server tests in Docker via `bash tests/run-server.sh`.

**Spec:** `docs/superpowers/specs/2026-11-18-brocante-design.md` (validated); mockup `maquette/brocante.html` (validated, local only).

## Global Constraints

- Tradable: wardrobe items of rarity commun, rare, epique, legendaire, and future event items. Never `ultra`, never `mythique` (explicit exclusion list, not « is in a draw pool »).
- A listing offers 1-3 items it owns; one item in at most one open listing; 3 open listings per player; 5 pending offers per player; one pending offer per player per listing.
- Bulletins: 0-20 per side, only alongside items or as the price of items; never a side made of bulletins alone against nothing.
- Listings never expire. Hidden (not deleted) when the author: has not been seen for 14 days, is suspended, is below `DUEL_MIN_LEVEL`, or has reached today's limit. Deleted with the author's account.
- To trade (list, take, offer, accept): level ≥ `DUEL_MIN_LEVEL` (5) and account ≥ 3 days (`MARKET.minAgeMs`, test knob `POLITIGO_MARKET_MIN_AGE_H`); 3 completed trades per player per server day (author and taker both count). Anyone not suspended may look.
- Both players must be eligible at the moment of the trade; a received item already owned is refused.
- A traded item leaves the giver's `wardrobe.own` (and `worn` if worn); nothing else changes in the draw.
- Same-network signal: one HMAC-SHA256 fingerprint of the last IP per player, server key kept in the settings table, overwritten, never the raw IP, never a history; console shows only « même réseau : oui / non ».
- No free text anywhere in listings or offers. No real money. No FM, XP, gauges or confetti through the Brocante.
- No spoilers in player-facing text (help, changelog, README): never mention the Bâton or ultra rares; say « certains objets très rares ne s'échangent pas ».
- French UI copy; compact existing code style; no new dependencies.
- Version 1.9.0 (player content = minor). Changelog entry dated the day of the work; update `web/changelog.mjs` with every visible change.
- Work on a branch from `dev` (`git checkout dev` first); commits end with `Co-Authored-By: Claude Opus 5.5 <noreply@anthropic.com>`; never commit `maquette/` or `.env`; never touch containers `politigo-web-1`, `politigo-api-1`, `politigo-admin-1` or host ports 8080/8090/8091.

## Review Focus

1. Two takers hit « Troquer » on the same listing, or the author accepts an offer while someone takes the listing: the second gets a clean 409 « Cette annonce n'est plus disponible. » and nothing is duplicated. → Task 4 test `two takers, one trade`.
2. The giver wears the item being traded: it leaves `worn` too; the receiver does not auto-wear it. → Task 1 test `applyTrade empties the worn slot of a given item`.
3. The author dies (level back to 1) with open listings: they vanish from the board and « Troquer » on a stale view is refused with the reason; they come back at level 5. → Task 4 test `author below the level: listing hidden, take refused`.
4. Between an offer and its acceptance, the offerer drew one of the listed items (now owns it) or lost an offered item: acceptance fails cleanly, the listing stays open. → Task 4 test `accept fails cleanly when the offer no longer holds`.
5. An account deleted with open listings and pending offers (both ways): its listings disappear, its offers close, accepting a closed offer answers 409, no crash. → Task 4 test `deleted author and offerer`.

  - Shapes: `Give = {items:string[], bulletins:number}`; `Want = {kind:"items",items:string[],bulletins} | {kind:"rarity",rarity,slot:"outfit"|"object"|"any",bulletins} | {kind:"bulletins",bulletins} | {kind:"offer"}`
  - `tradable(id) -> boolean` (in `ITEMS`, rarity not in `MARKET.excluded`)

  - `satisfies(want, give) -> boolean` (`items`: same set + exact bulletins; `rarity`: exactly one item of that rarity and slot + exact bulletins; `bulletins`: no item + exact bulletins; `offer`: always false)
  - `missing(S, give) -> string` French reason or "" (« Il te manque : X », « Il te manque N bulletins »)
  - `dupes(S, ids) -> string[]` ids already owned
  - `applyTrade(Sa, aGives, Sb, bGives) -> void` mutates both states; throws `Error` when either `missing` or a received item is a dupe (callers check first)
  - `tradeBlock(S, {minLevel, ageMs, today}) -> string` French reason or "" (« Échanges à partir du niveau 5. », « Ton compte est trop récent pour la Brocante. », « 3 échanges aujourd'hui : reviens demain. »)

### Task 2: Storage (`server/market.mjs`)

**Files:**
- Create: `server/market.mjs`
- Test: `tests/market.test.mjs`
- Modify: `tests/run-server.sh` and `server/Dockerfile` (mount/copy `server/market.mjs`)

**Interfaces:**
- Consumes: `cleanGive`, `cleanWant` (Task 1) — the module stores already-clean JSON.
- Produces: `createMarket(db) -> M` with tables `market_listings(id, player_id, give TEXT, want TEXT, created, status)`, `market_offers(id, listing_id, player_id, give TEXT, created, status)`, `market_trades(id, listing_id, offer_id, a_id, b_id, a_gave TEXT, b_gave TEXT, same_net INTEGER, created)`, `market_daily(day, player_id, n, PRIMARY KEY(day,player_id))`. Statuses: listing `open|traded|withdrawn|closed`; offer `pending|accepted|refused|closed|withdrawn`.
  - `M.list(playerId, give, want, now) -> id`; `M.listing(id)`; `M.openListings() -> rows`; `M.mine(playerId)`; `M.withdraw(id, playerId, now) -> boolean`
  - `M.offer(listingId, playerId, give, now) -> id`; `M.offerOf(id)`; `M.offersOn(listingId)`; `M.offersBy(playerId)`; `M.setOffer(id, status) -> boolean` (only from `pending`)
  - `M.trade({listingId, offerId|null, aId, bId, aGave, bGave, sameNet, now}) -> id` (marks listing `traded`, the offer `accepted`, other pending offers on it `closed`, increments both `market_daily`)
  - `M.today(playerId, day) -> n`
  - `M.closeUsing(playerId, itemIds) -> {listings:number[], offers:number[]}` closes that player's open listings / pending offers containing any of the items
  - `M.removePlayer(playerId)` deletes their open listings (status `closed`) and closes their pending offers and pending offers on their listings
  - `M.recent(limit) -> trades`; counts for limits: `M.openCount(playerId)`, `M.pendingCount(playerId)`, `M.pendingOn(listingId, playerId)`
  - Values are rows with parsed `give`/`want`/`a_gave`/`b_gave`.
